## preview 文档

经过了拷打之后，未来的 task5 大致的优化路线如下。

### task4 拷打

首先有一点就是得搞清楚 docker 的使用。在上一轮的学习中，我并没有真正的懂得如何去写 DockerFile，只是让 AI 跑的，所以，docker的基本使用得学会。

然后在 task5，要优化一下存储文件的方式。如果是本地存储的话，使用 MinIO，如果是云端存储的话，则是使用 AWS S3 或者 OSS。

然后就是有关于安全的问题，需要把一些敏感的东西，比如说 jwt 的密钥或者 redis 的密钥等，放置在一个专门的 config.yaml 中，然后使用 Viper 进行配置。

另外，utils 函数包的功能要单一，不能出现 c *app.RequestContext 之类的东西，不依赖于特定场景的使用。

再然后是数据库的问题，数据库可以使用 gorm-gen，比喻来看就是数据库脚手架，另外应该是得使用一个类来管理数据库，并且带 withContext ，来防止多个请求同时打到同一个函数上，造成奇怪的错误。同时，为了避免这个错误，应该在 service 层使用 Transaction 来管理数据库，数据库的每个函数应该是原子性的，不能出现多次查询数据库的情况。

还有一个问题就是，对于后端来说，软删除就是真正的删除了，不要想着去复原它。

还有就是关于 mw 的问题，虽然 redis 和 jwt 都术语中间件，但是他们位于的地方不一样。jwt 是有些函数需要调用的时候执行的，而 redis 则是访问外部的时候，二者性质不一样，所以 redis 层应该放在 dal 层。

还有一些问题，比如说在微服务架构要不要有本地 cache，答案是否定的，因为微服务架构是多个服务器运行，所以直接打入 redis 即可。

福uu 的架构还是传统的三层架构，所以可以看看字节青训营那个项目。

其他应该就没有什么需要注意的地方了，剩下的问题，比如说 test 文件等，这个放在第五轮解决。

### task5 计划实现

根据 task4 的文档以及考核要求，基本的实现步骤应该如下。

第一是重构为微服务架构，使用 kitex 重构，然后引入 etcd3 进行服务注册，在这些运行完毕后，应该先修正数据库和基本的安全问题，改为使用 gorm-gen，把数据库的每个函数原子化，每次调用都使用 withContext ，重构不合理的部分，并且使用 Transaction 进行管理，再然后是撰写 config.yaml，使用 Viper 进行部署，Viper 可以参考一下福uu。

进行到这里，可以开始研究一下 golangci-lint 等工具，优化一下代码质量，并且研究一下git 工作流，这里就可以重构一下了。

然后是研究一下单元测试，为每一个地方都部署一下，可以优化一下数据库的逻辑，感觉目前我比较薄弱的地方就是数据库的查询。

再然后就是研究一下分片上传（只是先分片上传，分布式存储后续可以等 task6 再看）

倒数第二个就是实现一下聊天以及聊天安全，最后就是研究 docker 相关的东西。
